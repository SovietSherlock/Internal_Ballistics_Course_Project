# Контрольный список сдачи — ЛР № 2

Контракт эксперимента — в [задании](01_assignment.md), структура текста — в [шаблоне](05_report_template.md), PDF — по [учебному профилю ГОСТ](02_gost_profile.md). Этот список не вводит новых сроков или оценок.

## 1. Постановка и математика

- [ ] Функция записана как f=x²+y²+a(2−cos4x−cos4y), основной a=1, контроль a=0; исследованы min и max.
- [ ] Ограничения x≤2, y≤3, x+y≥0,5 и охватывающий box [−2,5;2]×[−1,5;3] не изменены.
- [ ] Выведены вершины, объяснено существование экстремумов; обсуждена замена y≤3 на y<3.
- [ ] Контроль a=0 решён аналитически автором и сопоставлен с вычислениями. Основная сетка не выдана за точный глобальный эталон.
- [ ] Приведён градиент и независимая численная проверка; диагностические вызовы отделены от эксперимента.
- [ ] Используются g1=(x−2)/4,5, g2=(y−3)/4,5, g3=(0,5−x−y)/9; допустимость max(0,g1,g2,g3)≤10⁻⁶ проверяется до округления.
- [ ] P=sum(max(0,gi)²) един для штрафных SLSQP и TPE; минимизируется s·f+rho·P, s=+1 для min и −1 для max.

## 2. Методы и запуски

- [ ] SLSQP-C и DE-C используют explicit constraints и Bounds, не заменяют их штрафом.
- [ ] SLSQP-P использует Bounds и общий штраф, но не явное x+y≥0,5; TPE-P использует тот же штраф и диапазоны.
- [ ] Аналитические градиенты SLSQP и настройки всех методов соответствуют заданию и сохранены.
- [ ] DE: polish=False, workers=1; TPE: n_jobs=1, без вложенного оптимизатора и pruning; кэш цели и параллельность отключены.
- [ ] Основные опыты a=1: 4 метода × 2 направления × 5 run_id = 40 запусков; основной rho=100.
- [ ] Соответствие run_id=1…5: seeds [11,23,37,51,71], локальные старты [(-1,2), (0.25,0.25), (1.5,2.5), (-2,2.75), (1,-0.25)]. Это не декартово произведение.
- [ ] Дополнительно выполнены 20 опытов SLSQP-P при rho=1 и 10 для обоих направлений и пяти стартов. Rho=100 взят из main без дублирования. Исследование остальных rho для TPE необязательно.
- [ ] Контроль a=0: 8 опытов — run_id=1 каждого метода в обоих направлениях, основной rho. Обязательное ядро составляет 68 запусков.
- [ ] Независимые истории не склеены; дополнительные опыты явно отделены.

## 3. Бюджет и выбор результата

- [ ] На каждый независимый запуск установлен cap B=600 фактических скалярных вызовов f, включая повторы, начальные оценки и derivative probes, вызывающие f.
- [ ] Аналитические градиенты без f учитываются отдельно; число итераций/trials не подменяет n_eval.
- [ ] При cap выполняется контролируемая остановка до следующего f, а не возврат фиктивного значения. История сохраняется и без итогового объекта оптимизатора.
- [ ] Раннее завершение допустимо: сохранены фактические n_eval и причины остановки. Бюджет не добивается повторением точки.
- [ ] Рекомендация оптимизатора и лучшее допустимое по **всей истории** сохранены отдельно. Сравнение ведётся по исходному f лучшего допустимого.
- [ ] Если допустимых точек нет, указано «не найдено»; нет фиктивного нуля или недопустимого победителя.
- [ ] Графическая сетка и диагностики отделены от бюджета и истории поиска и не участвуют в выборе лучшего результата.

## 4. Данные и рисунки

- [ ] Сводки содержат n_eval, n_grad при применимости, остановку, рекомендацию оптимизатора, лучшее допустимое и ссылку best_eval_id. Пустые поля объяснены.

- [ ] До первой допустимой точки кривая не содержит фиктивного результата; ранняя остановка показана на фактическом конце.

## 5. Воспроизводимость и комплект

В архиве с одной корневой папкой присутствуют:

- [ ] report.md и report.pdf с одинаковыми содержательными результатами;
- [ ] main.py;
- [ ] pyproject.toml и uv.lock;
- [ ] figures с используемыми изображениями;
- [ ] results с журналами и конфигурацией;
- [ ] краткий LLM-протокол в отчёте по [форме](06_llm_protocol.md).

Проверены команды:

```bash
uv sync --frozen
uv run python main.py check
uv run python main.py run
uv run python main.py report
```

- [ ] check проверяет формулы, градиент, знак цели, штраф и cap на малом синтетическом примере, без полного эксперимента.
- [ ] run воспроизводит обязательные опыты без ручного ввода и LLM/API; повторный запуск не смешивает истории, его поведение описано.
- [ ] report пересоздаёт все таблицы-артефакты и рисунки из сохранённых данных без нового поиска и LLM/API. Авторский текст не обязан переписываться автоматически; PDF студент собирает своим инструментом.
- [ ] В архиве нет .venv, кэшей, секретов, полных LLM-чатов или гигантских notebook outputs. Ноутбук не является единственной реализацией.
- [ ] Пути переносимы и относительны, ссылки Markdown работают внутри комплекта.
