# Протокол проверки — лекция 2

Дата подготовки: 14.09.2026.

## Среда

Linux; CPython 3.13.5; uv 0.10.0; Jupyter kernel ipykernel 7.2.0.
Тест совместимости с pytest выполнен на pytest 9.0.2.
Версии среды проверки не заявляются как самые новые.

## Что реально выполнено

1. nbformat.validate для основного notebook и шаблона отчета.
2. AST-проверка всех Python-ячеек и исходных файлов проекта.
3. Выполнение всех 25 ячеек с кодом основного notebook в чистом Jupyter kernel.
4. Еще один полный проход в том же kernel: без ошибок; создается новая временная папка,
   предыдущая демонстрационная папка не перезаписывается.
5. Финальный независимый проход в новом kernel; сохранены выводы и номера 1–25.
6. `uv lock --offline` с реальным созданием uv.lock, без ручного сочинения lock-файла.
7. `uv sync --locked --offline` в новом окружении проекта: пакет собирается и устанавливается.
8. `uv run --locked --offline python -m course_motion`: пять ожидаемых строк.
9. `uv run --locked --offline python -m unittest discover -s tests -v`: пять тестов пройдено.
10. Код ячеек report_template.ipynb запущен интерпретатором созданной .venv из папки notebooks:
    импорт установленного пакета работает без изменения sys.path или PYTHONPATH.
    Отдельный Jupyter kernel в минимальную .venv для этой проверки не устанавливался.
11. Те же тесты запущены уже установленным pytest из папки src: пять тестов пройдено.
12. Проверка чувствительности тестов: в отдельной копии модели t_s**2 заменен на t_s;
    тестовый прогон завершается ошибкой, два теста обнаруживают дефект.
13. TOML/JSON разобраны; пути Dockerfile и настройки devcontainer статически проверены.
14. Notebook преобразован в HTML, просмотрены ключевые разделы; проверены якоря навигации,
    отсутствие общестраничного горизонтального переполнения и символов замены кодировки.

## Содержимое шаблона

Сторонних зависимостей времени выполнения нет. Базовые тесты используют unittest.
Поэтому исходный uv.lock содержит только сам проект. Для notebook добавьте `ipykernel`
через `uv add --dev ipykernel`, для JupyterLab — `uv add --dev jupyterlab`.
Эти команды намеренно изменят pyproject.toml и uv.lock; сохраните оба файла.
Это честный минимальный проект, а не фиктивный lock научного стека.

## Что НЕ проверено

- Установка программ на реальных Windows и macOS, выбор kernel в их графических интерфейсах.
- Команды, требующие скачивания Python, пакетов или образов: из среды подготовки нет сетевого
  доступа к соответствующим источникам. Синтаксис сверялся с официальными руководствами.
- Реальная сборка и открытие Dev Container: Docker недоступен в среде подготовки.
- Python 3.14: совместимость заявлена в диапазоне проекта, но отдельный прогон не выполнен.
- Получение одинаковых численных результатов вне заявленного контракта конечных числовых аргументов.

Среда разработки сама по себе не является безопасной песочницей. В архив не включены
виртуальные окружения, кэши, секреты и персональные студенческие работы.
