# Лабораторная работа № 1

## Markdown, LaTeX и воспроизводимый отчёт по прямому баллистическому расчёту

### 1. Цель работы

Освоить единый воспроизводимый цикл подготовки технического отчёта:

- реализовать расчёт на Python в виде запускаемого `uv`-проекта;
- проверить реализацию на осмысленно выбранном наборе баллистических решений;
- представить формулы в LaTeX, результаты — таблицами и графиками, пояснения — в Markdown;
- собрать из Markdown итоговый PDF по сокращённому учебному профилю ГОСТ 7.32;
- пройти предварительную проверку, взаимное ревью и внести исправления.

### 2. Содержательная постановка

Для своего варианта из таблицы `variants/variants.csv` разработайте функцию прямого расчёта, аналогичную по назначению `full_calc` из `консульт 2.ipynb`, но учитывающую именно данные и математическую модель вашего варианта.

Функция должна для заданного баллистического решения:

1. сформировать входные данные для `pyballistics`;
2. выполнить расчёт при нормальной начальной температуре `+20 °C` и при температурах, которые встречаются в индивидуальных ограничениях варианта;
3. определить длину ствола по достижению заданной дульной скорости при `+20 °C`;
4. вычислить критерий варианта;
5. проверить два общих и два индивидуальных ограничения;
6. вычислить выбранную автором штрафную функцию;
7. вернуть данные, достаточные для диагностики, построения всех рисунков и объяснения результата.

Вариант задаёт:

- калибр `d`, массу снаряда `q` и требуемую дульную скорость `v_pm`;
- тип орудия: нарезное (`НР`) или гладкоствольное (`ГС`);
- модель: нульмерную (`НМ`) или квазиодномерную (`КМ`);
- критерий `W_pm` либо `Z_B1`;
- общие ограничения `p_m^max` и `l_m^max`;
- два индивидуальных ограничения.

Модель менять нельзя. Для `НМ` используется нульмерная модель библиотеки, для `КМ` — квазиодномерная модель. Примеры вызовов обеих моделей есть в консультационных материалах.

### 3. Общие исходные данные

- Давление воспламенителя: `p_ign_0 = 5 МПа`.
- Давление форсирования: `p_0 = 30 МПа` для нарезного орудия и `p_0 = 15 МПа` для гладкоствольного.
- Для нарезного орудия площадь поперечного сечения канала ствола

  $$
  S = 0.26\pi d^2,
  $$

  что соответствует `n_S = 1.04` при записи `S = n_S πd²/4`. Для гладкоствольного орудия принимается `n_S = 1.00`.
- Воспламенитель — порох ДРП.
- Начальные температуры: `−50 °C = 223.15 K`, `+20 °C = 293.15 K`, `+50 °C = 323.15 K`.
- Используется актуальная на начало работы версия `pyballistics`; фактически разрешённая версия должна быть зафиксирована в `uv.lock`.

Марку пороха или состав смеси, относительную массу заряда `ω/q`, плотность заряжания `Δ`, диапазоны изменения параметров и набор проверочных решений студент выбирает самостоятельно и обосновывает. Допускается заряд из одной марки либо смесь нескольких порохов.

### 4. Логика расчёта

Базовый расчёт выполняется при `+20 °C`. Интегрирование должно завершаться по одной из диагностируемых причин: достижение требуемой скорости, превышение предельной длины, превышение давления, ошибка модели либо иной явно обработанный предел.

Если требуемая скорость достигнута, полученное положение снаряда принимается за длину ведущей части ствола `l_m`. Затем расчёты при иных требуемых температурах выполняются до того же положения `l_m`, чтобы получить дульные характеристики при фиксированной геометрии.

Для каждого результата необходимо сохранить как минимум:

- входные параметры решения и фактическую версию `pyballistics`;
- причину останова и статус расчёта;
- временные или пространственные зависимости, нужные для графиков;
- `l_m`, максимальное среднебаллистическое давление, дульную скорость и дульное давление;
- максимальное ускорение, положение полного сгорания и долю сгоревшего пороха — если эти величины нужны варианту;
- значения всех ограничений, величины их нарушения и итоговый признак допустимости;
- исходный критерий, отдельные штрафы, суммарный штраф и штрафованный критерий.

Внутренняя структура функции может быть любой, но перечисленная информация не должна теряться за одним логическим флагом `isgood`.

### 5. Критерии

Для критерия объёма канала ствола вместе с каморой используется

$$
W_{pm}=W_0+Sl_m, \qquad W_0=\frac{\omega}{\Delta}.
$$

Меньшее значение `W_pm` считается лучшим.

Критерий В. Е. Слухоцкого `Z_B1` реализуется по формуле из § 2.4 методического пособия:

$$
Z_{B1}=
\left(\frac{qv_{pm}^2}{2\omega}\right)
\left(\frac{qv_{pm}^2}{2x_{pm}}\right)^4
\sqrt{N_s}
=
\frac{(qv_{pm}^2)^5}{2^5\omega x_{pm}^4}\sqrt{N_s},
$$

где

$$
N_s=K(1+\Lambda_m)\frac{q}{\omega}.
$$

Большее значение `Z_B1` считается лучшим. Все обозначения и принятое значение общей константы `K` требуется явно указать. Если при сравнении решений постоянный положительный множитель опускается, это надо прямо написать и доказать, что ранжирование не изменяется.

### 6. Ограничения

При `+20 °C` для каждого варианта обязательно проверяются:

$$
p_m \le p_m^{\max}, \qquad l_m \le l_m^{\max}d.
$$

Направления индивидуальных ограничений:

| Обозначение в варианте | Смысл | Условие |
|---|---|---|
| `p_mz,T` | дульное среднебаллистическое давление при температуре `T` | не более заданного |
| `g_p,T` | максимальное ускорение снаряда при `T` | не более заданного |
| `v_pm,−50` | дульная скорость при `−50 °C` | не менее заданного |
| `η_e,T` | относительное положение снаряда в момент полного сгорания при `T` | не более заданного |
| `ψ_p,T` | относительная масса сгоревшего пороха в момент вылета при `T` | не менее заданного |

Определения вычисляемых величин и способ извлечения их из результата выбранной модели должны быть описаны в отчёте. Значения ограничений берутся из своей строки таблицы вариантов без изменения.

### 7. Штрафная функция

Штрафную функцию выберите самостоятельно и обоснуйте. Единой обязательной формулы нет.

По реализации и объяснению должно быть видно, что:

- внутри допустимой области штраф равен нулю или не ухудшает критерий;
- штраф монотонно возрастает с величиной нарушения;
- ограничения с разными размерностями разумно масштабированы или нормированы;
- исходный и штрафованный критерии хранятся раздельно;
- для минимизируемого `W_pm` штраф ухудшает значение вверх;
- для максимизируемого `Z_B1` штраф ухудшает значение вниз либо используется явно объяснённое эквивалентное преобразование;
- вычислительная ошибка не маскируется под обычное нарушение без отдельного статуса;
- выбранные коэффициенты и форма штрафа проверены хотя бы на нескольких значениях нарушения.

В этой лабораторной работе штраф нужен для проверки корректности вычислительной логики. Подключать оптимизатор и искать оптимальное решение не требуется.

### 8. Проверочный набор баллистических решений

Составьте небольшой, но доказательный набор точек. Набор должен включать:

1. не менее одной допустимой точки, если её удалось получить;
2. точки, демонстрирующие срабатывание каждого из четырёх ограничений;
3. не менее одной пары близких точек по разные стороны выбранной границы либо обоснованное приближение к ней;
4. точки с разной величиной нарушения для проверки монотонности штрафа;
5. при наличии — корректно обработанный случай, когда расчёт не завершился штатно.

Одна точка может использоваться в нескольких проверках, но графики и таблица должны позволять установить, какое именно ограничение сработало. Избегайте набора, в котором все недопустимые точки одновременно нарушают всё: он плохо диагностирует ошибки.

Способ поиска точек не оценивается как оптимизация. Разрешены ручной подбор, грубая сетка, случайная выборка с фиксированным seed или иной воспроизводимый способ.

### 9. Графики и инфографика

Готового обязательного списка графиков нет. В начале основной части отчёта сформулируйте, какие утверждения надо проверить и в каких координатах они становятся видимыми.

Возможные, но не обязательные формы представления:

- карта проверенных точек в координатах `(ω/q, Δ)` с кодированием статуса;
- зависимости давления, скорости, ускорения, `ψ` от времени или координаты;
- диаграмма нормированных запасов по ограничениям;
- зависимость исходного и штрафованного критерия от величины нарушения;
- сравнительные кривые для температур `−50`, `+20`, `+50 °C`;
- таблица паспортов выбранных точек.

Каждый рисунок должен отвечать на сформулированный вопрос. На нём должны быть подписаны оси и единицы, указаны сравниваемые точки и границы; цвета не должны быть единственным носителем смысла. После рисунка нужен краткий вывод, а не пересказ легенды.

### 10. Структура отчёта

Отчёт выполняется в `report.md`; формулы набираются в LaTeX, рисунки хранятся в `figures/`. Итоговый `report.pdf` компилируется самим студентом любым выбранным инструментом. Инструментарий сборки сдавать не требуется.

Обязательные блоки:

1. титульный лист;
2. **Введение** — цель и границы работы;
3. **Вариант и план проверки** — исходные данные, математическая модель, критерий, ограничения, выбранные параметры решений, замысел графиков и инфографики;
4. **Реализация и штрафная функция** — контракт функции, вычисление показателей, формула и обоснование штрафа;
5. **Выбор проверочных точек и результаты** — таблица точек, графики и краткий анализ;
6. **Заключение** — что именно подтверждено, какие ограничения реализации остались;
7. **Список использованных источников**;
8. **Приложение А** — полный текст собственного программного кода либо точная ссылка на включённый в сдачу `main.py` с существенными фрагментами. Отдельный `.py` обязателен в любом случае.

Оформление выполняется строго по `02_gost_profile.md`, а не по всем необязательным элементам полного ГОСТ.

### 11. Состав сдачи

Отправляется один ZIP-архив. После распаковки структура должна быть такой:

```text
lab1_<Фамилия>/
├── pyproject.toml
├── uv.lock
├── main.py
├── report.md
├── report.pdf
└── figures/
    └── ... все рисунки, на которые ссылается report.md
```

Для исправленной сдачи дополнительно требуется `changes.md`.

Команда

```bash
uv sync --frozen
uv run python main.py
```

должна без ручных действий пересоздать **все** рисунки, использованные в отчёте. Пути должны быть относительными; входные данные варианта и выбранные точки должны находиться в коде или в файлах проекта, а не в локальных каталогах автора. Интерактивный ввод, ноутбук как единственная реализация и предварительно созданные вручную рисунки не допускаются.

`uv.lock` должен соответствовать `pyproject.toml`. В консоли при запуске выведите фактическую версию `pyballistics` и краткий итог по каждой проверочной точке.
